# 产品线 10 · 3D演示（等距结构图）

> 把一个概念/系统/算法画成一台**看得懂的机器**：等距投影、实心部件、可交互、能打印。
> 对外名：**3D演示**。内部工艺名：等距工艺图（isometric crafted figure）。

## 何时进这条线

```
用户要：把机制讲清楚 / 结构说明图 / 装置示意 / 「画得像真的机器」
关键词：原理图、结构图、怎么工作的、拆开看看、等距、isometric、工艺感
✅ 适合：一个机制、一台设备、一条数据通路、一个算法流程
❌ 不适合：数据图表（走信息图）· 氛围插画（走插画）· 需要照片级渲染（走 3D 建模）
```

## ① 规格

```
三档尺寸（先定档，再动手）
  Figure  一个机制 · 40-80 个部件 · 至多 1 层 WebGL · 通常 1 小时内
  Hero    复杂装置 · 80-150 部件 或 1 个可转动主体 · 约 2-4 小时
  Epic    整车/整厂/多主体 3D · 6 小时以上 · **默认不接**，先提案 Hero 版
技术形态  框架无关 TS/JS 直写 SVG+HTML；也支持 React/Next
导出      交互 HTML + PNG（2x）+ A4 PDF（可选）
性能边界  静态图无限制；可转动 3D 为 beta（小图 60fps；380 部件在手机档 13-20fps）
运行时    Node.js ≥20.10 + Chrome/Chromium
```

## ② 必填要素（缺一不算交付）

```
□ 档位已声明（Figure / Hero / Epic），Epic 需用户明确选择
□ 真实数字已核对（尺寸/计数/阈值/曲线）—— 读数、运动、图注三者必须都真
□ 一句话说清「什么在动、这个动代表什么」
□ 部件清单 ≥40（分 base / structure / mechanism / controls / subject 五组）
□ 恰好一个部件是 lit（读者该盯的那个），不许两个主角
□ 默认交付静态等距图；可转动作为加项单独确认
```

## ③ 流程四步（来自 anatomy 的 Workflow）

```
Step 1  Size it        先定档并声明工时量级（Epic 只提案不直接开工）
Step 2  Truth first    先收真实数字与行为；能写成纯模块（如 rig.ts）就写，让一切由它驱动
Step 3  Invent object  选一台机器，机构与概念一一对应；**不抄参考图，取 finish 不取 object**
Step 4  Parts list     写 ≥40 个部件并分组 → 才动几何（质量 80% 在这一步决定）
```

## ④ 门禁五条（craft rules，逐条打勾）

```
1. Solids, not wireframes —— 每个部件实心填充、按序绘制；前面遮住后面
   ❌ 透视线框 · ❌ 虚线隐藏线
2. Let the kit shade —— 有高度的部件用 extrude（四侧色级 + 更亮顶面）；只有地板/薄嵌件用 flat
3. Tone hierarchy —— base/feet = lo，structure = mid，subject = hi；**恰好一个 lit**
4. Small precise detail —— 倒角 0.4-1.6 · 凹槽内缩 3-5 · 螺丝 0.4-0.55 带环 · 刻度每 4-5 一档
5. Lines resolve —— 每条线都落在东西上（面/另一条线/端点）
   ❌ 引线 · ❌ 气泡标注 · ❌ 尺寸箭头 · ❌ 漂浮文字
```

## 常见返工点

```
· 画成「示意图」不是「工艺图」：加了引线箭头、透明线框、彩色乱配（违反门禁 1/3/5）
· 先画几何再补部件清单 → 结构讲不通，返工重画
· 数字凭记忆（不核对真实尺寸/阈值）→ 读数与图注对不上，读者一验就发现
· 直接开工 Epic → 6 小时起，方向错了全废
· 默认就给可转动 3D → beta 且吃性能，用户以为卡了
```
