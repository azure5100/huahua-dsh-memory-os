# HOS 设计说明 · 七色光谱花蕊

> 适用：`huahua-dsh-memory-os`（简称 **HOS**）
> 资产：`icon.svg`（插件图标，根目录，由 `package.json` 的 `"icon"` 指向）· `docs/brand/banner.svg`（品牌横幅）
> 版本：2026-10-19

---

## 一、定位：HOS 是什么，不是什么

**HOS 是宿主层的「长期记忆 + 背景复盘」插件**，不是一个聊天前端，也不是一个工作流编排器。

它做的事只有三件：

| 层 | 干什么 | 对应的真实能力 |
|---|---|---|
| **记** | 把事实、偏好、项目约定、当日进展**分层落盘** | `memory` 五轨：`memory` / `user` / `project` / `key` / `daily` |
| **用** | 让这些记忆在**下一轮生成前**自动回到上下文 | `key` 轨自动注入 · 每轮收尾批量写 · 到期提醒 |
| **看** | 把「我到底记得什么、项目在干什么」变成**可观测的面板** | 11 个 Tab（记忆 / 技能 / 待办 / 模型 / 广播 / 同步 / 人事部 …）|

**它明确不做的事**（这决定了图标不该像什么）：

- ✗ 不是"AI 助手头像"——它是**基础设施**，不扮演人格
- ✗ 不是"大脑"图形——大脑是通用隐喻，说不了"分层与可检索"
- ✗ 不是"齿轮"——它不是配置工具，是**记忆的容器**

---

## 二、设计目标（图标必须回答的三个问题）

1. **它是"记忆"吗？** ⇒ 要有**内核**（有中心，不是散开的图形）
2. **它"分层"吗？** ⇒ 要有**层次**（中心／环／外瓣三层，而不是单层色块）
3. **它"活着"吗？** ⇒ 需要有**呼吸与旋转**的余地（源设计带动效，图标取静态帧）

---

## 三、图形语言

```
        花瓣 × 7            中心双环
     ┌─────────────┐     ┌──────────────┐
     │ 向外伸展     │     │ 外环 = 边界容器 │
     │ 等分 51.43° │     │ 内点 = 索引/可检索 │
     └─────────────┘     └──────────────┘
```

### 3.1 七色光谱 —— 为什么是"光谱"而不是"七个图标"

七片花瓣**不是七个功能清单**，而是**一条连续光谱在 7 个等分点上的采样**。

这一点必须说清，因为 HOS 的记忆轨本身就是**连续的**：

```
daily（今天）→ project（这个项目）→ key（本项目关键）→ user（这个人）→ memory（所有项目）
```

这五条轨不是五个并列的抽屉，而是**同一个人在不同时间尺度上的切片**。
用色块拼接会画成"五个抽屉"；用**光谱**才画得出"切片"。

> 如果一定要一一对应，作者留过一个提案（**仅为提案，不是语义锁**）：
> 记忆(红) · 技能(橙) · 待办(黄) · 模型(绿) · 广播(青) · 同步(蓝) · 人事部(紫)。
> 之所以不把它写死：HOS 的 Tab 集合会变（现在是 11 个），而**光谱不会变**。

### 3.2 中心双环 —— "单一真相源"的几何表达

| 元素 | 语义 | 对应 HOS 的实际设计 |
|---|---|---|
| 外环（r=25，描边 1.5）| **容器 / 边界** | 记忆有边界：`memory` 与 `project` 不混写，`key` 按分支过滤 |
| 内点（r=8.5）| **索引 / 可检索** | 记忆不是堆着的文本，是**能被检索回来**的条目 |
| 环与瓣之间的暗底 | **内核与能力的分界** | 内核（记忆）稳定，瓣（能力）可增删——加一个 Tab 不改内核 |

### 3.3 几何规范

| 项 | 值 | 说明 |
|---|---|---|
| viewBox | `0 0 300 300` | 正方形，便于任何尺寸等比 |
| 花瓣路径 | `M150 150 C116 118 118 74 150 44 C182 74 184 118 150 150 Z` | 单瓣，贝塞尔对称 |
| 花瓣角度 | `51.43° × n` | = 360 / 7，等分 |
| 旋转原点 | `150 150` | 与中心同心 |
| 中心半径 | 25 / 8.5 | 外环 / 内点 |

## 四、色彩规范

| 名 | HEX | 用于 |
|---|---|---|
| 朱 | `#FF5A4E` | 光谱起点 |
| 橙 | `#FF9A3C` | |
| 黄 | `#FFD93D` | |
| 绿 | `#3DDC84` | |
| 青 | `#35C4D9` | |
| 蓝 | `#4C7DFF` | |
| 紫 | `#A855F7` | 光谱终点 |
| 底 | `#131722 → #0d0f14` | 中心暗底（径向渐变）|
| 墨 | `#f4f6fb` | 中心内点 |
| 边 | `#e8ecf4` | 外环描边 |

**为什么是这七个色**：它们在同一明度带上（L* ≈ 65–75），**并排不打架**；
换成饱和度不齐的七色（如纯红 + 浅黄 + 深紫）会在 24px 尺寸下碎成噪点。

**深底优先**：这套色在 `#0d0f14` 上最亮；放到白底会把黄与橙吃掉。
若必须上浅底，请**只保留外环与内点**（单色版），不要把七色直接贴白。

## 五、用法规范

| 场景 | 做法 |
|---|---|
| 插件列表图标 | 直接用 `icon.svg`（宿主按 `package.json` 的 `"icon"` 读取）|
| 24px 以下 | 七色会糊成灰 ⇒ 建议改用**单色版**（只留环 + 点）|
| 品牌横幅 | `docs/brand/banner.svg`（1200×400，含 wordmark 与色带）|
| 留白 | 图形占画布 100%，不做额外内边距；宿主会自己加 padding |
| 禁止 | ✗ 拉伸非等比 · ✗ 加投影/发光 · ✗ 旋转图标本身（旋转是**动效**，不是静态姿态）|

## 六、动效（源设计保留值）

图标是**静态帧**，但源设计是动的。若将来做启动动画，用这两组值：

```
spin    : 26s linear infinite            transform-origin: 150px 150px
breathe : 4.5s ease-in-out infinite      opacity 0.52 → 1 → 0.52
          每瓣延迟 0.18s 递进（0 / .18 / .36 / .54 / .72 / .90 / 1.08）
```

**为什么图标不做动效**：插件图标出现在**列表**里，同屏有十几个；一起转会把列表变成风车。
动效留给"启动页"与"空状态"，那时**只有一个**花蕊，旋转才成立。

## 九、动态版花蕊（docs/brand/spectrum-bloom.gif）

源设计是一段**动画**（26s 旋转 + 4.5s 逐瓣呼吸）。GitHub 的 README / Release 里
**SVG 动画会被剥离**，所以这里给出**逐帧渲染的 GIF** —— 不是录屏，是按几何**重算**的。

| 项 | 值 | 说明 |
|---|---|---|
| 画布 | 600×600，超采样 3× 后降采样 | 抗锯齿 |
| 帧数 | 74 帧 @ 20 fps ≈ 3.714 s | |
| 循环弧长 | **51.43° = 360/7** | 花瓣等分 ⇒ 转一格与起始帧**视觉全等** ⇒ **无缝循环** |
| 呼吸 | 0.80 → 1.00，逐瓣相位差 0.18 s | 源设计下限 0.52 在大面积纯色下显脏，动图抬到 0.80 |
| 中心 | 不参与透明度 | 环与内点保持不透明，压在花瓣之上 |

**为什么把 26 s 缩成 3.7 s**：完整一圈 26 s 的 GIF 会到二十多 MB。用「转一格 = 一圈」的对称性，把周期压到 **1/7**，观感完全相同而体积降到 1.9 MB。

**为什么抬高呼吸下限**：源设计逐瓣错峰，单瓣低透明度看起来像擦除；但 GIF 里 7 瓣面积占比大，0.52 会让整朵发灰 ⇒ 抬到 0.80 保住饱和度。

## 十、艺术字（docs/brand/wordmark.svg / wordmark.png）

两个名字必须**同时出现**：HOS 是给用户的简称，huahua-memory-os 是包名。所以做成**上主下副**的双层字标，而不是两个独立 logo。

    花蕊   H O S                  ← 主字：7 色横向渐变（红→紫，与花瓣同序）
          huahua-memory-os        ← 副字：等宽体 + 大字距，连字符调灰
          ▬▬▬▬▬▬▬                  ← 七色色带（与图标同七色）
          HUA HUA · MEMORY OS · SEVEN-COLOR SPECTRUM BLOOM

**设计要点**

| 元素 | 做法 | 理由 |
|---|---|---|
| 主字渐变 | 按**文字包围盒**映射 7 个停靠点 | 按画布映射会让 H 吃掉全部七色、OS 全灰（第一版就踩了这个坑）|
| 主字字距 | 18–20 px 手动逐字排 | 让 HOS 三个字母的负空间与花瓣间隙接近 |
| 副字 | 等宽体（Cascadia Mono → Consolas → Courier 回退）| 等宽体的机械感与「基础设施」定位一致 |
| 连字符 | 调成 #7c869c | 让 huahua-memory-os 读起来是三段，而不是一长串 |
| 花蕊标记 | 缩到主字高度约 1.15 倍，放左上 | 第一版按 1.9 倍放，压住了 H |

**为什么同时给 .svg 和 .png**

- .svg —— 可编辑，改字改色都行；但 <text> 依赖宿主字体，GitHub 上会用回退字体渲染
- .png —— 锁死外观，发布页 / README 用它，保证任何人看到的都是同一张
