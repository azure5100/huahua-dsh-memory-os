> 日期: 2026-07-19
> 状态: 设计确定，待实施

---

## 一、核心问题

### 1.1 当前问题

1. **Orchestrator 全生命周期管理不完善** — 找到人之后谁负责组织协作、分任务、验收、交付？缺乏项目主管角色贯穿全流程
2. **团队边界漂移** — 长周期、多轮对话中，团队成员角色模糊化，出现越界行为
3. **缺乏协作机制** — 团队搭建起来后，1+1 > 2 的效果没有充分发挥
4. **缺乏文件体系** — 过于依赖大模型会话记忆，记忆会偏移，缺乏定格记录

### 1.2 核心理念

> **专家 = 一堆提示词告诉 agent 该怎么做事、从哪里下手、方法论。**
> 大模型是巨大的图书馆，专家知道怎么用这个图书馆。

- 专家必须有边界，有自己的方法论和做事逻辑
- 更优秀的专家能做自我迭代、突破现有知识库
- 团队协作要靠文件驱动，不依赖模型记忆

## 二、整体架构

```
人事部系统（系统级知识）
  └── 人事部团队模板（可复用模板）
       └── 团队文件夹（团队级汇总）
            └── 项目文件夹（项目级存档）
                 └── 项目资料（蓝图/施工/纪要）
```

**文件逐层上升，经验逐层沉淀。**

## 三、角色层：项目牧羊人

### 3.1 角色定位

| 项目 | 内容 |
|:-----|:------|
| **角色** | `agents/project-management-project-shepherd` |
| **职责** | 组织协调、进度监管、边界纠偏、汇报交付 |
| **定位** | **执行者**，Orchestrator 流程是"轨道" |
| **原则** | 组织专家制定方案，**不替代专家做专业决策** |

### 3.2 在 Orchestrator 中的介入节点

| 阶段 | 项目牧羊人职责 |
|:-----|:--------------|
| Stage 0-0.8 预检 | 参与需求澄清、可行性判断 |
| Stage ① 方案设计 | **组织团队成员共同编写项目蓝图** |
| Stage ② 分工派活 | 分配任务、设定边界声明 |
| Stage ③ 并行交付 | 进度监管、协调阻塞、边界纠偏 |
| Stage ④-⑤ 验收联调 | 组织验收、质量把关 |
| Stage ⑥ 项目交付 | 汇总施工报告、录入 gbrain |
| Stage ⑦ 报告归档 | 输出项目纪要，触发团队模板固化 |

## 四、入职流程

### 4.1 完整入职链路

```
人事部匹配专家（ROLE-INDEX 匹配 266 个角色）
       ↓
团队搭建（确定项目牧羊人 + 成员阵容）
       ↓
Step 1: 角色定义注入
  ├── 项目牧羊人从 source/<dept>/<role>.md 读取完整角色定义
  ├── 角色定义 + 项目信息 → 注入团队成员 system prompt
  └── 输出【角色任命书】（含边界声明）
       ↓
Step 2: 蓝图对表
  ├── 项目牧羊人组织团队会议
  ├── 分发蓝图草案，每个成员对照角色定义确认分工
  ├── 调整边界声明
  └── 全员确认 → 锁定 → 写入施工文件
       ↓
Step 3: 入职确认
  └── 项目牧羊人确认全员到位、角色理解无误
       ↓
开始施工 → 每个 Stage 入口执行阶段注入
```

## 六、边界保障机制

### 6.1 三层防护

| 层次 | 机制 | 说明 |
|:-----|:-----|:------|
| **蓝图锚定（A）** | 开工前项目牧羊人组织读蓝图 | 每个成员确认自己的边界声明 |
| **文件自检（B）** | 施工文件首部写边界声明 | 偏移时自查回正 |
| **项目牧羊人监督** | 主动检测角色偏移 | 发现→纠偏→记录偏差日志 |

### 6.2 纠偏流程

```
项目牧羊人检测到角色偏移
    ↓
判断：轻微偏离？严重越界？
    ↓
轻微 → 提醒成员重新阅读边界声明
严重 → 重新注入角色定义 + 边界声明
    ↓
记录到偏差日志（L3_项目纪要）
```

## 八、角色迭代机制

### 8.1 反哺流程

```
项目完工 → 项目牧羊人汇总经验教训
    ↓
分析每个角色在项目中的表现
    ├── 频繁越界 → 角色定义边界不清 → 补充边界声明
    ├── 展现未预期能力 → 拓展角色定义
    └── 项目经验 → 更新模板"注意事项"
    ↓
更新 source/<dept>/<role>.md
```

### 8.2 变更记录规范

每次更新角色定义必须附带**更新日志**：

```markdown
## 更新日志
| 日期 | 版本 | 变更内容 | 原因 | 触发项目 |
|------|------|---------|------|---------|
| YYYY-MM-DD | v2.1 | 补充边界声明 | 项目中发现频繁越界 | nango-xxx |
| YYYY-MM-DD | v2.0 | 拓展能力描述 | 展现了未预期能力 | nango-yyy |
```
